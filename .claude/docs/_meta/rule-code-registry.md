# Rule-Code Registry — реестр префиксов правил

Единый источник правды: какой префикс — общий (язык-нейтральный, один на все языки) и какой —
языко-специфичный. Новый код — **сначала запись здесь**, потом использование (см. `authoring-contract.md` §5).

Scope:
- **shared** — код означает одно на всех языках; меняется только реализация в `<домен>/references/<lang>/implementation.md`.
- **java** / **python** — языко-специфичный concern, у каждого языка своя пара гайдов.
- **meta** — про сам процесс/формат, вне языков.

## Суб-семейства `R-SPECFMT-*` (формат Use Case спецификации)

Правила формата спеки живут в `shared/spec-format/spec.md`; проверяются `ucp-spec-review` (категория `SR-RD`),
применяются `ucp-spec-design` и `ucp-spec-tier-0`. Конвенция §5: `-<N>` — MUST, `-X<N>` — антипаттерн.

| Суб-семейство | Коды | О чём |
|---|---|---|
| `TBL` — таблицы | `R-SPECFMT-TBL-1`, `R-SPECFMT-TBL-2` · антипаттерны `-X1`, `-X2` | `TBL-1`: перечень 3+ однородных элементов — таблицей со стабильными заголовками; `TBL-2`: таблица не шире 6 колонок, шире — две связанные по общему ключу |
| `LEAD` — лид | `R-SPECFMT-LEAD-1`, `R-SPECFMT-LEAD-2` · антипаттерн `-X1` | `LEAD-1`: перед §1 раздел «О сервисе» на 5–10 строк прозой (чем занимается · 2–3 потока · 2–3 риска); `LEAD-2`: «О юните» на 2–3 строки в файле домен-юнита |
| `EVD` — evidence | `R-SPECFMT-EVD-1` · антипаттерн `-X1` | Ссылка на источник — вне предложения: колонка `Evidence`, блок «Источники раздела» или сноска; в прозе — имя класса/файла без номера строки |
| `ND` — пробелы | `R-SPECFMT-ND-1`, `R-SPECFMT-ND-2` · антипаттерн `-X1` | `ND-1`: хвостовой ненумерованный раздел «Что не определено» вместо россыпи `not-declared` по прозе; `ND-2`: литерал остаётся по месту в ячейках таблиц и полях карточек |
| `PRG` — прогрессивное раскрытие | `R-SPECFMT-PRG-1` · антипаттерн `-X1` | Раздел открывается 1–3 предложениями прозой, только потом таблицы и карточки |
| `LNG` — язык | `R-SPECFMT-LNG-1` · антипаттерн `-X1` | Короткие предложения, активный залог, термины из Ubiquitous Language; канцелярит и безличный пассив — антипаттерн |

Разведение с машиночитаемостью (`PRG` ↔ `TBL-1`, `ND` ↔ `TBL-1`, `EVD` ↔ реестры §11) — таблица
«Разведение правил подачи и машиночитаемости» в `shared/spec-format/spec.md`.

## Классификация concern'ов (kind: NEUTRAL / IMPL-SHAPED / LANG-SPECIFIC)

Задаёт, сколько живёт в shared-слое и как строго держать нейтральность (см. `authoring-contract.md` §11).
Граница нейтральности shared-индексов enforced машинно: `_meta/check-shared-neutral.py` (D).

| Kind | Concern'ы |
|---|---|
| **NEUTRAL** (полный нейтральный shared-индекс) | usecase-pattern, ddd-tactical, cqrs, distributed-patterns, rest-api, error-handling, validation, pg-* (типы/именование/индексы/миграции/runtime), arch |
| **IMPL-SHAPED** (тонкие принципы в shared, механизм/тюнинг в биндинге) | resilience, kafka, caching, observability, graceful-shutdown, hexagonal, auth-patterns, security, scheduler, payment-integration, streaming |
| **LANG-SPECIFIC** (нет shared-слоя) | `backend/java/`: jooq, java-style, spring-bootstrap, test-strategy · `backend/python/`: sqlalchemy, python-style, python-bootstrap, python-test-strategy, codegen, async |

## Ось специализации (track)

Вторая ось, ортогональная языку (см. `authoring-contract.md` §10). Все префиксы выше — **backend-трек**
(implicit-default). Новые специализации резервируют свой префикс здесь до использования.

| Track | Concern-набор (черновик) | Стек | Префикс | Статус |
|---|---|---|---|---|
| `backend` | usecase-pattern, ddd, cqrs, kafka, … (всё выше) | java/python/node/go | (без track-токена) | инкумбент |
| `frontend` | процедура поверх требований проекта: экран, форма, сервис, права, тесты | React + TS (шаблоны frontend-templates) | requirement ID проекта, своих кодов нет | наполнен |
| `e2e` | набор сквозных сценариев и его прогон вокруг выкатки | язык-нейтрален | требования `e2e-suite/*`, `e2e-pipeline/*` | наполнен |
| `any` | spec, arch, meta, review-format, new-service | — | (свои: `R-ARCH-*`, `R-SPECFMT-*`, `SR-*`, `RFF-*`) | кросс-трековое ядро |

Дальше — `mobile`/`data`/`infra` по рецепту `authoring-contract.md` §10. Скиллы: `ucp-fe-*` / `ucp-e2e-*`.

**Замечание по «flavored».** Большинство shared-индексов сейчас содержат Java-флейвор в формулировках
(annotations в скобках). При добавлении Python-реализации соответствующий `<concern>-rules.md`
генерализуется (как сделано для `error-handling`) — framework-токены уходят в per-language справочник,
коды и интент остаются. Это разовая работа на concern в момент, когда к нему добавляют второй язык.
