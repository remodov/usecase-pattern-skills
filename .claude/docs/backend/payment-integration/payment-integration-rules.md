# Payment Integration — индекс правил (язык-нейтральный)

> **Что это.** Outbound-интеграция с внешним платёжным провайдером: идемпотентный флоу
> (создать→списать→финализировать), anti-corruption маппинг статусов провайдера в доменные,
> разделение транспортных и бизнес-ошибок, дозабор незавершённых операций (reconciliation).
> Concern класса **IMPL-SHAPED** — shared-индекс фиксирует **принципы и инварианты**, а механизм
> (HTTP-клиент, конкретные вызовы, тюнинг) живёт в per-language style-guide.
> На какие style-guide ссылаться: `payment-integration/<lang>/payment-integration-style-guide.md`.
> Коды: `R-PAYINT-<N>` — обязательно (MUST), `R-PAYINT-X<N>` — антипаттерн (MUST NOT).
> Сшивки: фоновый дозабор/конкурентный захват — `scheduler-rules.md` (`R-JOB-*`); идемпотентность —
> `distributed-patterns-rules.md` (`R-DIST-IDEM-*`); retry/timeout/CB — `resilience-rules.md` (`R-RES-*`);
> структура out-adapter — `integration` (`R-RES-OAS-*`, `R-LAY-*`); иерархия ошибок — `error-handling-rules.md`
> (`R-ERR-*`).

Суть: оплата через внешнего провайдера — **at-least-once** распределённая операция. Корректность держится
на идемпотентности (повтор безопасен), различении «временно недоступно» и «отказано», и едином доменном
представлении статуса — а не на том, что вызов «прошёл ровно один раз».

## 1. Идемпотентный флоу провайдера
**MUST:**
- **R-PAYINT-1.** Операция оплаты идемпотентна по **natural idempotency key** (уникальный ключ заказа/платежа): повтор того же ключа не создаёт второй платёж у провайдера.
- **R-PAYINT-2.** Перед созданием операции у провайдера — **read-before-write**: сначала запросить статус по natural key; если операция уже создана — переиспользовать её, не создавать заново (cross-ref `R-DIST-IDEM-*`).
- **R-PAYINT-3.** Списание выполняется **только если операция ещё не в терминальном состоянии** (act-only-if-not-terminal); повторный вызов на завершённой операции — no-op.
- **R-PAYINT-4.** Конкурентные запросы на оплату одного и того же доменного заказа сериализуются (claim/lock), чтобы не создать два параллельных платежа (cross-ref `R-JOB-DUP-1`).

**MUST NOT:**
- **R-PAYINT-X1.** Создание операции у провайдера без предварительной проверки natural key — риск двойного платежа.
- **R-PAYINT-X2.** Списание без проверки текущего состояния операции.

## 2. Anti-corruption маппинг статусов
**MUST:**
- **R-PAYINT-5.** Единый **stateless-маппер** «статус провайдера → доменный статус», общий для онлайн- и фонового путей; коды провайдера интерпретируются в одной точке.
- **R-PAYINT-6.** Наружу из адаптера отдаются **доменные** статусы/значения, не сырые DTO/коды провайдера (cross-ref `R-LAY-*`).
- **R-PAYINT-7.** Обновление доменной записи по результату — **частичное** (только изменившиеся поля), без затирания неуказанных.

**MUST NOT:**
- **R-PAYINT-X3.** Дублирование интерпретации кодов провайдера в нескольких местах (разъезд логики).
- **R-PAYINT-X4.** Утечка DTO/кодов провайдера выше границы адаптера в домен/хендлер.

## 3. Транспортная ошибка vs бизнес-отказ
**MUST:**
- **R-PAYINT-8.** Транспортная/временная ошибка провайдера (таймаут, 5xx, сеть) → операция остаётся в **повторяемом** состоянии; её доберёт следующий проход. Не финализировать как окончательный отказ.
- **R-PAYINT-9.** Бизнес-отказ провайдера (явный отказной код) → перевод в **терминальное** состояние (отказано).
- **R-PAYINT-10.** Транспортные ошибки оборачиваются в **port-specific** исключение/тип, отличимое от бизнес-отказа (cross-ref `R-ERR-*`, `R-RES-*`).

**MUST NOT:**
- **R-PAYINT-X5.** Финализировать платёж как FAILED по транспортной ошибке (теряется реально прошедшая оплата / ложный отказ).
- **R-PAYINT-X6.** Единый `catch` без различения транспорт/бизнес.

## 4. Reconciliation незавершённых операций
**MUST:**
- **R-PAYINT-11.** Незавершённые операции добираются фоновым проходом: атомарный захват батча + финализация по актуальному статусу провайдера (cross-ref `R-JOB-*`).
- **R-PAYINT-12.** Просроченные «висящие» операции закрываются по TTL (cutoff в UTC, cross-ref `R-JOB-TIME-1`).

**MUST NOT:**
- **R-PAYINT-X7.** Полагаться только на онлайн-путь без дозабора — при сбое связи операции зависнут.

## 5. Денежные величины
**MUST:**
- **R-PAYINT-13.** Суммы — точный десятичный тип; перевод в минорные единицы (копейки/центы) — с явным округлением half-up, не через двоичный float.

**MUST NOT:**
- **R-PAYINT-X8.** `float` для денег и `int(float_amount * 100)` для минорных единиц — ошибки округления.

## 6. Наблюдаемость и аудит
**MUST:**
- **R-PAYINT-14.** Денежные операции логируются с natural key/идентификатором для трассировки повторов; метрики успех/отказ/недоступность провайдера (cross-ref `R-OBS-*`).
- **R-PAYINT-15.** Чувствительные данные (PAN, секреты, токены провайдера) не попадают в логи/события/ошибки (cross-ref `R-SEC-*`).

**MUST NOT:**
- **R-PAYINT-X9.** Логирование номеров карт/секретов провайдера.
- **R-PAYINT-X10.** Денежная операция без следа (нельзя восстановить, что и когда произошло).
