# PostgreSQL Partitioning — индекс правил

> **Что это.** Сжатый индекс правил `pg-partitioning-style-guide.md`: код + формулировка, по разделам. Рабочий вход
> для скиллов — review цитирует код в findings, design сверяется по чек-листу. **Полная версия
> с SQL-примерами и обоснованием — `pg-partitioning-style-guide.md`**; открывай её точечно по разделу.
> Коды: `PG-P-<NNN>`. X-кодов нет; сводные антипаттерны — `PG-P-08X` в разделе 10.

Партиционирование — инструмент для **больших** таблиц; для маленьких overhead больше выигрыша. Главный выигрыш — управляемость (мгновенный `DROP` старых данных, autovacuum per-партиция).

## 1. Когда оправдано
**MUST:**
- **PG-P-001.** Партиционируй, если хотя бы одно: таблица > 50 GB / 100M строк и растёт; time-series; старые данные регулярно дропаются по сроку; multi-tenant с очень крупными тенантами; autovacuum не справляется.
- **PG-P-002.** Избыточно, если: таблица < 10 GB; запросы редко включают partition key в `WHERE`; нет данных для дропа по сроку.

## 2. Базовый паттерн
**MUST:**
- **PG-P-003.** PK партиционированной таблицы обязан включать ключ партиционирования (`PRIMARY KEY (id, occurred_at)` при `PARTITION BY RANGE (occurred_at)`).

## 3. Три типа
**MUST:**
- **PG-P-010.** RANGE — самый частый (time-series, архивы по году/месяцу).
- **PG-P-011.** LIST — фиксированный набор категорий (регионы `'EU'`/`'US'`/`'APAC'`).
- **PG-P-012.** HASH — равномерное распределение без естественного ключа; не даёт pruning по диапазону, помогает только при `WHERE key = ?`.
- **PG-P-013.** HASH оправдан редко — чаще «равномерно распределить» решается одной таблицей с правильными индексами.

## 4. Выбор ключа
**MUST:**
- **PG-P-020.** Ключ должен быть в `WHERE` почти всех запросов — иначе pruning не работает. Правильно: `PARTITION BY occurred_at` / `tenant_id`; неправильно: `BY status`, если ходят по `customer_id`.
- **PG-P-021.** Если запросы делятся на две группы — выбирай ключ, что чаще в самых тяжёлых; композитный partition key обычно overkill.
- **PG-P-022.** Распределение нагрузки сравнимое по партициям; 99% в одной — не партиционирование. Проверь перед выбором.

## 5. Размер партиции
**MUST:**
- **PG-P-030.** Целевой размер — 1–50 GB (больше — autovacuum тормозит, меньше — overhead планировщика). Time-series: помесячно/понедельно/подневно по нагрузке.
- **PG-P-031.** Не делать сотни мелких партиций: > 1000 тормозит планировщик, > 10000 — кластер еле дышит.

## 6. Управление
**MUST:**
- **PG-P-040.** Создавать новые партиции заранее (на месяц-два вперёд) — иначе `INSERT` без подходящей партиции упадёт; ручной cron или `pg_partman`.
- **PG-P-041.** Удаление старых данных — `DROP TABLE` партиции, не `DELETE` (мгновенно, без MVCC-следов и WAL).
- **PG-P-042.** `DETACH PARTITION` отделяет без удаления данных (перенос в холодное хранилище); PG14+ — `DETACH ... CONCURRENTLY`.

## 7. Индексы на партициях
**MUST:**
- **PG-P-050.** `CREATE INDEX` на родительской таблице автоматически создаёт индексы на каждой партиции; можно partial per-партиция при разной нагрузке.
- **PG-P-051.** Уникальные индексы должны включать ключ партиционирования (уникальность гарантируется только в пределах партиции).

## 8. Foreign Keys
**MUST:**
- **PG-P-060.** Partitioned table → FK на обычную таблицу работает.
- **PG-P-061.** Обратное (обычная → partitioned) — с PG12+; партиция-источник должна иметь PK с ключом партиционирования (`PG-P-003`).

## 9. Миграция существующей таблицы
**MUST:**
- **PG-P-070.** Прямого `ALTER TABLE ... PARTITION BY` нет — миграция через теневую таблицу (`CREATE ... LIKE INCLUDING ALL PARTITION BY` → партиции → `INSERT SELECT` батчами → `RENAME` в одной транзакции).
- **PG-P-071.** На таблице 500 GB — несколько часов копирования + место под обе версии; планируй заранее.

## 10. Антипаттерны
**MUST NOT:**
- **PG-P-080.** Партиционировать малые таблицы (< 10 GB) — overhead больше выигрыша.
- **PG-P-081.** Партиционировать по полю, которого нет в большинстве `WHERE`.
- **PG-P-082.** Multi-tenant per-tenant партиции на сотнях тенантов — autovacuum и pg_class распухают; лучше RLS или partial indexes.
- **PG-P-083.** Множество мелких партиций (по часам/минутам) — > 1000 тормозит планировщик.
- **PG-P-084.** Забыть создать партицию заранее — `INSERT` упадёт.
- **PG-P-085.** `UPDATE` поля partition key — PG переместит строку (`DELETE+INSERT`), большой WAL; partition key делай immutable.
