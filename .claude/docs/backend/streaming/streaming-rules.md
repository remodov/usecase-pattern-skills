# Streaming & Real-time — индекс правил (язык-нейтральный)

> **Что это.** Долгоживущие/потоковые соединения: server-sent events (однонаправленный поток server→client),
> двунаправленный канал (WebSocket), потоковая выгрузка тела ответа (большие файлы/отчёты). Concern класса
> **IMPL-SHAPED** — shared-индекс фиксирует **принципы** (выбор механизма, auth на установлении, backpressure,
> heartbeat, отмена при разрыве, ресурсы, масштабирование), а механизм/API — в per-language style-guide.
> На какие style-guide ссылаться: `streaming/<lang>/streaming-style-guide.md`.
> Коды: `R-STREAM-<N>` — обязательно (MUST), `R-STREAM-X<N>` — антипаттерн (MUST NOT).
> Сшивки: соединение/событийный цикл — `async` (`PYASYNC-*`); закрытие на shutdown — `graceful-shutdown` (`R-SHUT-*`);
> auth на handshake — `auth-patterns` (`AUTH-*`); сессии БД на соединение — `sqlalchemy` (`R-SQLA-SESS-*`);
> fan-out через брокер — `kafka`/`caching` (pub/sub); метрики — `observability` (`R-OBS-*`).

Суть: потоковое соединение живёт долго и держит ресурсы. Корректность — это выбрать минимально достаточный
механизм, аутентифицировать на установлении, ограничивать буферы и число соединений, освобождать ресурсы при
разрыве и не привязывать состояние к памяти одного инстанса.

## 1. Выбор механизма
**MUST:**
- **R-STREAM-1.** Механизм по природе обмена: однонаправленный поток server→client → **SSE**; двунаправленный интерактив → **WebSocket**; разовая выгрузка большого тела → **потоковый ответ** (chunked), не загрузка целиком в память.

**MUST NOT:**
- **R-STREAM-X1.** WebSocket там, где достаточно SSE/poll — лишняя сложность (reconnect, heartbeat, масштабирование) без двунаправленности.
- **R-STREAM-X2.** Формирование всего большого ответа в памяти вместо потоковой выдачи (OOM на больших выгрузках).

## 2. Аутентификация и авторизация на установлении
**MUST:**
- **R-STREAM-2.** Аутентификация **на установлении соединения** (handshake): токен валидируется до приёма, не «доверяем первому кадру» (cross-ref `AUTH-1/4`).
- **R-STREAM-3.** Авторизация на подписку/канал: проверка прав на конкретный ресурс/комнату, не только факт аутентификации (cross-ref `AUTH-10`).

**MUST NOT:**
- **R-STREAM-X3.** Открытый поток без проверки токена на handshake (особенно WebSocket — он не проходит обычный HTTP-auth middleware так же, как REST).
- **R-STREAM-X4.** Бессрочное соединение без переучёта истёкшего токена/прав для долгоживущих сессий.

## 3. Backpressure и лимиты
**MUST:**
- **R-STREAM-4.** Ограничение буфера/скорости на медленного потребителя: при переполнении — отбрасывать/коалесцировать/закрывать соединение, не копить бесконечно.
- **R-STREAM-5.** Лимит числа одновременных соединений на инстанс (защита от исчерпания дескрипторов/памяти).

**MUST NOT:**
- **R-STREAM-X5.** Неограниченная очередь исходящих сообщений на соединение — медленный клиент → рост памяти → OOM.

## 4. Heartbeat и таймаут простоя
**MUST:**
- **R-STREAM-6.** Keepalive/heartbeat (ping или комментарий-кадр) для обнаружения «мёртвых» соединений и удержания через прокси; таймаут простоя закрывает зависшие.

**MUST NOT:**
- **R-STREAM-X6.** Соединение без heartbeat/idle-timeout — зависшие копятся, потребляя ресурсы, разрывы не детектируются.

## 5. Отмена при разрыве и ресурсы
**MUST:**
- **R-STREAM-7.** Разрыв клиента отменяет серверную работу по этому соединению (остановить продьюсер/итерацию, освободить подписки/ресурсы) — cross-ref `PYASYNC-6` (отмена).
- **R-STREAM-8.** Не удерживать тяжёлые ресурсы на всё время соединения: БД-сессию/транзакцию открывать на единицу работы (per-chunk/per-message), не на весь поток (cross-ref `R-SQLA-SESS-1`).

**MUST NOT:**
- **R-STREAM-X7.** Продолжать генерировать/слать в уже закрытый канал (трата ресурсов, ошибки записи).
- **R-STREAM-X8.** Держать открытую транзакцию/сессию БД на всю длительность соединения (пул исчерпывается, долгие транзакции).

## 6. Масштабирование (несколько инстансов)
**MUST:**
- **R-STREAM-9.** Состояние «кто на что подписан» и доставка fan-out не привязаны к памяти одного инстанса: рассылка между инстансами через брокер/шину (pub/sub), либо sticky-маршрутизация — осознанно.

**MUST NOT:**
- **R-STREAM-X9.** Broadcast из in-memory реестра соединений одного инстанса — клиенты на других репликах не получат событие.

## 7. Наблюдаемость
**MUST:**
- **R-STREAM-10.** Метрики: число активных соединений, длительность, темп сообщений, разрывы/ошибки; алерт на аномалии (cross-ref `R-OBS-*`).

**MUST NOT:**
- **R-STREAM-X10.** Полный payload потоковых сообщений/PII в логах (объём + утечка); логировать события соединения и идентификаторы (cross-ref `R-OBS-LOG-X1`).
