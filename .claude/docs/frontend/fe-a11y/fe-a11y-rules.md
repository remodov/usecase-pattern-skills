# Доступность — индекс правил (React + TS, @design-system/components)

> **Что это.** Concern `fe-a11y` трека `frontend` (стек React+TS, дизайн-система **@design-system/components**).
> Single-stack → плоская форма: коды + интент + примеры внутри (отдельного style-guide нет). Коды: `FE-A11Y-<N>` —
> обязательно, `FE-A11Y-X<N>` — антипаттерн. Карта трека — `frontend/_index.md`.
>
> **Реализация под проект:** компоненты `@design-system/components` (`Button`, `Link`, `Tabs`, `Modal`, `Input`,
> `Status`, `Badge`, …) доступны по умолчанию — несут корректные роли/aria/управление фокусом. Опора на ДС, а не
> на кастомный интерактив из `div`. Связанные: `fe-component` (семантика вью, не div-суп), `fe-forms` (label и
> доступность ошибок поля — Formik + core-components), `fe-styling` (ДС-компоненты доступны из коробки, кастом не
> ломает их семантику).

## 1. Семантика и роли
**MUST:**
- **FE-A11Y-1.** Интерактив — через семантические элементы/компоненты ДС с нативной ролью (`Button`, `Link`, `Tabs`, `Checkbox`), не через `div`/`span` с `onClick`; роль и клавиатура приходят даром.
- **FE-A11Y-2.** Структура страницы — семантическими лендмарками (`nav`/`main`/`header`/`footer`) и иерархичными заголовками (`h1…h_n` без скачков), а не цепочкой `div` со стилями.
- **FE-A11Y-3.** Кнопке нужен видимый или доступный текст; иконочная кнопка без подписи получает доступное имя (`aria-label`/визуально скрытый текст).

**MUST NOT:**
- **FE-A11Y-X1.** `div`/`span` с `onClick` как кнопка/ссылка — нет роли, нет фокуса, не активируется Enter/Space, невидим для screen reader.
- **FE-A11Y-X2.** Кастомный интерактив (свой select/tabs/checkbox из `div`) вместо компонента ДС — теряются роль, aria и клавиатура, которые ДС даёт из коробки.

## 2. Формы и подписи
**MUST:**
- **FE-A11Y-4.** Каждое поле формы имеет программно связанный `label` (компонент ДС `Input`/`Select` со `label`, либо `htmlFor`↔`id`); `placeholder` — не замена label.
- **FE-A11Y-5.** Ошибки валидации доступны у поля: текст ошибки рядом + связь (`aria-describedby` на текст ошибки, `aria-invalid` на невалидном поле) — компоненты ДС делают это через проп `error` (cross-ref `fe-forms`).
- **FE-A11Y-6.** Группы полей и обязательность выражены семантически (`fieldset`/`legend` для группы радио, признак обязательности — в тексте/aria, не только звёздочкой-цветом).

**MUST NOT:**
- **FE-A11Y-X3.** Поле без связанного label (только `placeholder` или подпись-`div` рядом без связи) — screen reader не озвучит назначение поля.
- **FE-A11Y-X4.** Сообщение об ошибке только визуально (красная рамка/текст без связи с полем) — недоступно при навигации по полям.

## 3. Клавиатура и фокус
**MUST:**
- **FE-A11Y-7.** Весь интерактив достижим и управляем с клавиатуры (Tab — перемещение, Enter/Space — активация, Esc — закрытие оверлеев); порядок фокуса соответствует визуальному.
- **FE-A11Y-8.** В диалогах/модалках — управление фокусом: фокус переходит внутрь, удерживается (focus trap), Esc закрывает, при закрытии возвращается на триггер; используй `Modal` ДС, не самодельный оверлей.
- **FE-A11Y-9.** Видимый индикатор фокуса (`focus-outline`) сохраняется; если переопределяешь — даёшь равноценную видимую замену (`:focus-visible`).

**MUST NOT:**
- **FE-A11Y-X5.** Снятие `outline: none` (или `:focus`-стиля) без видимой замены — клавиатурный пользователь теряет позицию.
- **FE-A11Y-X6.** Положительный `tabindex` (`tabindex > 0`) или ручная перестройка порядка, ломающие естественную последовательность фокуса; `tabindex` — только `0`/`-1` по необходимости.

## 4. Цвет, не-цветовые сигналы и aria
**MUST:**
- **FE-A11Y-10.** Смысл/состояние передаётся не только цветом: добавь текст или иконку-с-подписью (`Status`/`Badge` ДС с текстом, а не голая цветная точка).
- **FE-A11Y-11.** Значимые иконки/изображения имеют доступное имя (`alt`, `aria-label`); чисто декоративные — скрыты от screen reader (`alt=""`, `aria-hidden`), чтобы не зашумлять озвучку.
- **FE-A11Y-12.** `aria-*` применяй точечно — закрыть пробел семантики, которого нет в нативном элементе/компоненте ДС, не дублируя уже имеющуюся роль.

**MUST NOT:**
- **FE-A11Y-X7.** Состояние закодировано только цветом (валидно/ошибка/выбрано — лишь оттенком) — недоступно при дальтонизме и нехватке контраста.
- **FE-A11Y-X8.** Значимая иконка/картинка без доступного имени, либо, наоборот, декоративная озвучивается (нет `aria-hidden`/`alt=""`).
- **FE-A11Y-X9.** Избыточные/неверные `aria`, дублирующие нативную семантику (`role="button"` на `Button`, `aria-label`, повторяющий видимый текст) — шум и рассинхрон для screen reader.

## 5. Чеклист подключения (React + TS, core-components)
1. Интерактив — семантика/компоненты ДС (`Button`/`Link`/`Tabs`), не `div` с `onClick`; страница — лендмарки и иерархия заголовков.
2. У каждого поля — связанный label; ошибки доступны (`error`-проп ДС / `aria-describedby` + `aria-invalid`).
3. Всё управляемо с клавиатуры; модалки — `Modal` ДС с trap/Esc/возвратом фокуса; видимый focus-outline сохранён.
4. Состояние не только цветом (`Status`/`Badge` с текстом); значимые иконки имеют имя, декоративные скрыты.
5. `aria-*` — только чтобы закрыть пробел семантики, без дублирования нативной роли.
