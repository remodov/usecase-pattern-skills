# Frontend Components — индекс правил (React + TypeScript)

> **Что это.** Concern `fe-component` трека `frontend` (стек React+TS). Single-stack → плоская форма: коды + интент
> + код-примеры внутри (отдельного style-guide нет). Коды: `FE-CMP-<N>` — обязательно, `FE-CMP-X<N>` — антипаттерн.
> Связанные: `fe-state` (состояние не в компоненте-вью), `fe-data-fetching` (запросы не в компоненте),
> `fe-a11y` (семантика), `fe-test` (тест юзер-центричный).
>
> **Статус: эталон формы каркаса.** Принципы ниже — стартовый набор; FE-лид расширяет/уточняет под свой проект.

## 1. Разделение ответственности
**MUST:**
- **FE-CMP-1.** Презентационные компоненты (как выглядит) отделены от контейнерных (откуда данные/логика): вью получает данные и колбэки через props, не ходит за ними сам.
- **FE-CMP-2.** Бизнес-логика и запросы — **не во вью-компоненте**: данные — через `fe-data-fetching` (хуки), состояние — через `fe-state`. Компонент рендерит то, что пришло.
- **FE-CMP-3.** Один компонент — одна ответственность; разрастается (>~150 строк / несколько забот) — декомпозируй.

**MUST NOT:**
- **FE-CMP-X1.** `fetch`/прямой вызов API внутри презентационного компонента (cross-ref `FE-DATA-*`).
- **FE-CMP-X2.** Бизнес-правила (расчёты цен, права) в JSX — выноси в хуки/утилиты/доменный слой.

## 2. Props и типизация
**MUST:**
- **FE-CMP-4.** Props типизированы явным `type`/`interface`; никакого `any`. Обязательные vs опциональные — через тип, не рантайм-проверки.
- **FE-CMP-5.** Узкие, доменные props (`OrderSummary`, не «прокинуть весь объект и 10 флагов»); булевы — `is/has/can`.

**MUST NOT:**
- **FE-CMP-X3.** `any`/`object` в props; prop-drilling через 3+ уровня — поднять в контекст/стор (`fe-state`).
- **FE-CMP-X4.** Мутация props или передаваемых объектов — props иммутабельны.

## 3. Композиция и переиспользование
**MUST:**
- **FE-CMP-6.** Композиция через `children`/слоты вместо булевых флагов-режимов, разветвляющих рендер.
- **FE-CMP-7.** Переиспользуемые UI-примитивы — в общий ui-слой/дизайн-систему (cross-ref `fe-styling`).
- **FE-CMP-10.** Многочастный компонент собирается **compound-паттерном**: общий стейт — через React Context, части-подкомпоненты вешаются на родителя (`Form.Input`, `Form.Select`) и читают контекст хуком `useX()`, который **бросает ошибку при использовании вне провайдера**. Это вместо prop-drilling одних и тех же пропсов через все части (cross-ref `fe-forms` `FE-FORM-10`).

**MUST NOT:**
- **FE-CMP-X5.** «God-компонент» с десятком булевых пропов-режимов вместо композиции.
- **FE-CMP-X8.** Чтение Context без гварда (`useContext` напрямую с молчаливым `undefined`) у compound-частей — вместо хука, бросающего при использовании вне провайдера (`FE-CMP-10`).

## 4. Перформанс и эффекты
**MUST:**
- **FE-CMP-8.** Мемоизация (`memo`/`useMemo`/`useCallback`) — **точечно по факту проблемы**, не превентивно на всё.
- **FE-CMP-9.** `useEffect` — только для синхронизации с внешним миром; деривативные данные считать при рендере, не в эффекте; зависимости полные и честные.

**MUST NOT:**
- **FE-CMP-X6.** `useEffect` для вычисления стейта из пропсов (лишний ре-рендер) — считай прямо.
- **FE-CMP-X7.** Преждевременная тотальная мемоизация без замеров — шум и баги в зависимостях.

## 5. Чеклист подключения (React + TS)
1. Вью отделено от контейнера; данные/колбэки — через props.
2. Запросы и бизнес-логика — вне вью (`fe-data-fetching` / `fe-state`).
3. Props типизированы, без `any`, доменные и узкие; props иммутабельны.
4. Композиция через `children`, не флаги-режимы; примитивы — в дизайн-систему.
5. Мемоизация и `useEffect` — по факту, зависимости честные.
