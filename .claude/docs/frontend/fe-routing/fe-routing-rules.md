# Роутинг (React + TS, react-router 6)

> **Что это.** Concern `fe-routing` трека `frontend` (стек React+TS, **react-router 6**). Single-stack → плоская
> форма: коды + интент + примеры внутри (отдельного style-guide нет). Коды: `FE-RT-<N>` — обязательно,
> `FE-RT-X<N>` — антипаттерн. Карта трека — `frontend/_index.md`.
>
> **Реализация под проект:** централизованная типизированная константа `ROUTES` (через `createRoutes<T>(...)`),
> каждый роут — `{ path, roles?, title? }`; хелпер `getRoutePath(route)`; параметризованные пути через
> `generatePath`. Набор ключей `ROUTES` ↔ `COMPONENTS` сшит типами (`ROUTES_VALUES`). Guard по ролям —
> централизованно на границе роутера (пересечение `route.roles` с ролями пользователя из стора). Связанные:
> `fe-state` (роли пользователя — из стора, `userRolesSelector`, не из локального состояния), `fe-component`
> (вью не зашивает в себя выбор маршрута и проверку прав), `fe-data-fetching` (загрузка данных роута — в
> контейнере страницы, не в роут-конфиге).

## 1. Централизация маршрутов
**MUST:**
- **FE-RT-1.** Все пути живут в единой типизированной константе `ROUTES` (`createRoutes<T>(...)`), каждый роут — `{ path, roles?, title? }`; новый раздел добавляется здесь, а не строкой по месту.
- **FE-RT-2.** Путь для навигации/ссылки берётся из `ROUTES` через `getRoutePath(ROUTES.X)` (параметризованный — `generatePath(getRoutePath(ROUTES.X), { clientId })`), а не собирается строковым литералом.
- **FE-RT-3.** Список роутов и список их компонентов — единый сшитый по ключам набор (`ROUTES` ↔ `COMPONENTS` → `ROUTES_VALUES`), типобезопасный; рендер роутов идёт из одного источника.

**MUST NOT:**
- **FE-RT-X1.** Хардкод path-строк по компонентам (`navigate('/clients/' + id)`, `path='/clients'`) вместо `ROUTES` + `getRoutePath`/`generatePath` — магические строки рассыпаются и ломаются при смене пути.
- **FE-RT-X2.** Дублирование списка роутов в нескольких местах без сшивки по типам — два рассинхронизирующихся источника правды о маршрутах.

## 2. Guard'ы по ролям/auth
**MUST:**
- **FE-RT-4.** Защищённый роут декларирует доступ полем `roles?: UserRoles[]` на самом роуте в `ROUTES`; отсутствие `roles` означает осознанно общедоступный роут.
- **FE-RT-5.** Доступ проверяется **централизованно на границе роутера** (пересечение `route.roles` с ролями пользователя), а не ad-hoc в каждом компоненте по-своему; нет прав → единый редирект/`NotFound`/`AccessDenied`.
- **FE-RT-6.** Роли пользователя для guard'а берутся из стора (`fe-state`, `userRolesSelector`), а не из props/локального состояния глубокого компонента.
- **FE-RT-11.** Guard реализован как **декларативный проход по единому списку** (`ROUTES_VALUES.map`): для каждого роута доступ = `intersection(route.roles ?? [], userRoles ?? [])`; пустые `roles` → роут публичный. Пока роли пользователя не загружены, защищённый контент не «протекает» (гейт по факту наличия ролей), а не показывается на миг до проверки.

**MUST NOT:**
- **FE-RT-X3.** Чувствительный раздел отрендерен роутом без `roles` (и не общедоступен по смыслу) — фактически незащищённый роут.
- **FE-RT-X4.** Проверка прав, продублированная ad-hoc внутри страницы (`if (!roles.includes(ADMIN)) return null`) вместо централизованного guard — расходящаяся логика доступа.

## 3. Параметры и навигация
**MUST:**
- **FE-RT-7.** Параметры пути типизированы и читаются через `useParams<{ clientId?: string }>()` с явным типом; отсутствующий параметр обрабатывается явно (дефолт/`NotFound`).
- **FE-RT-8.** Навигация — только средствами react-router: `useNavigate()` / `<Link>` / `generatePath`; для внешних URL — обычная ссылка, но не для внутренних переходов.
- **FE-RT-9.** Решение «куда перейти» принимается в контейнере/обработчике страницы; глубокий презентационный компонент получает колбэк, а не зашивает выбор маршрута в себя (cross-ref `fe-component`).

**MUST NOT:**
- **FE-RT-X5.** Нетипизированные params (`useParams()` без типа, `params as any`) — потеря контроля над формой URL.
- **FE-RT-X6.** `window.location.href = ...` / `history.pushState` для внутренней навигации вместо `useNavigate`/`<Link>` — полная перезагрузка, потеря состояния роутера.

## 4. Code-splitting
**MUST:**
- **FE-RT-10.** Тяжёлые разделы/страницы подключаются лениво (`React.lazy`) и оборачиваются `Suspense` с осмысленным `fallback` (спиннер/скелет); деление по роуту — естественная граница чанка.

**MUST NOT:**
- **FE-RT-X7.** `React.lazy` без `Suspense`-fallback (или с пустым fallback) — белый экран/рантайм-ошибка при загрузке чанка.

## 5. Чеклист подключения (React + react-router 6)
1. Путь — в `ROUTES` (`createRoutes`), берётся через `getRoutePath`/`generatePath`, не строкой по месту.
2. `ROUTES` ↔ `COMPONENTS` сшиты по ключам (один источник для рендера роутов), без рассинхрона.
3. Защищённый роут декларирует `roles`; доступ проверяется централизованно на границе роутера, роли — из стора.
4. Params типизированы (`useParams<T>`), навигация через `useNavigate`/`<Link>`/`generatePath`, не `window.location`.
5. Тяжёлые страницы — `React.lazy` + `Suspense` с fallback; выбор маршрута — в контейнере, не в глубоком вью.
