# Стилизация и дизайн-система (React + TS, @design-system/components)

> **Что это.** Concern `fe-styling` трека `frontend` (стек React+TS, **дизайн-система `@design-system/components`**).
> Single-stack → плоская форма: коды + интент + примеры внутри (отдельного style-guide нет). Коды: `FE-STY-<N>` —
> обязательно, `FE-STY-X<N>` — антипаттерн. Карта трека — `frontend/_index.md`.
>
> **Реализация под проект:** UI-примитивы — из `@design-system/components` **deep-import по компоненту**
> (`@design-system/components/button`, `/input`, `/typography`, `/grid`, `/select`, `/table/components`, `/tabs`,
> `/badge`, `/status`); иконки — `@design-system/icons`. Раскладка — `Grid`,
> типографика — `Typography` (Title/Text). Layout-стили — CSS-модули (`*.module.css`); цвета/отступы — из токенов
> дизайн-системы. Связанные: `fe-component` (примитивы выносим в ui-слой, не верстаем во вью), `fe-a11y`
> (компоненты ДС доступны по умолчанию — не ломать их разметку).

## 1. Примитивы из дизайн-системы
**MUST:**
- **FE-STY-1.** Там, где в `@design-system/components` есть аналог, используй компонент ДС, а не сырой html-тег: `Button` вместо `<button>`, `Input` вместо `<input>`, `Select`, `Checkbox`, `Table` (`/table/components`) вместо ручной верстки.
- **FE-STY-2.** Текст и заголовки — через `Typography` (`Typography.Title` / `Typography.Text`), а не сырые `<h1>`/`<p>`/`<span>` с ручными стилями шрифта.
- **FE-STY-3.** Раскладку (колонки, ряды, gutter) строй на `Grid` из ДС (`@design-system/components/grid`), а не на самописных flex/float-обёртках с магическими отступами.

**MUST NOT:**
- **FE-STY-X1.** Сырой `<button>`/`<input>`/`<select>`/`<h1>`/`<table>` там, где есть готовый компонент ДС — теряются состояния, токены, доступность (`fe-a11y`).
- **FE-STY-X2.** Переизобретение существующего компонента ДС (свой «кастомный Button/Modal/Badge» копипастой) вместо использования и расширения готового.

## 2. Импорты дизайн-системы
**MUST:**
- **FE-STY-4.** **Deep-import конкретного компонента**: `import { Button } from '@design-system/components/button'` — тянется только нужный модуль, бандл не раздувается.
- **FE-STY-5.** Иконки — точечным импортом из `@design-system/icons` по имени иконки, а не пачкой «на всякий случай».

**MUST NOT:**
- **FE-STY-X3.** Импорт пакета целиком (`import { Button, Input } from '@design-system/components'`) — в бандл утягивается вся дизайн-система.
- **FE-STY-X4.** Barrel-реэкспорт всей ДС через локальный `index.ts`, превращающий любой импорт в импорт всего пакета (теряется tree-shaking).

## 3. Токены, типографика, раскладка
**MUST:**
- **FE-STY-6.** Цвета — из токенов дизайн-системы (CSS-переменные `var(--color-...)` / цветовые пропы компонентов), а не произвольные hex/rgb по месту.
- **FE-STY-7.** Отступы, радиусы, размеры шрифта — из токенов/шкалы ДС (`var(--gap-...)` и т.п.) и пропов компонентов (`size`, `view`), а не магические px.
- **FE-STY-8.** Вид/состояние примитива задавай документированными пропами ДС (`view`, `size`, `block`, `loading`), а не перекрывай его стили снаружи.

**MUST NOT:**
- **FE-STY-X5.** Хардкод цвета (`#11A0FF`) или размера (`margin: 13px`) вместо токена/пропа — рассинхрон с темой ДС.
- **FE-STY-X6.** «Подкрутка» внутренностей компонента ДС через `!important` / селекторы по его внутренним классам — ломается при обновлении версии.

## 4. CSS-модули vs инлайн-стили
**MUST:**
- **FE-STY-9.** Layout и оформление — в CSS-модулях (`*.module.css`), классы подключаются через `styles.foo`; имена классов доменные, не презентационные (`.summary`, не `.red`).
- **FE-STY-10.** Инлайн-`style` — только для **динамических** значений, вычисляемых в рантайме (прогресс `width: ${percent}%`, координаты), не для констант оформления.

**MUST NOT:**
- **FE-STY-X7.** Инлайн-`style` с константой оформления (хардкод-цвет/размер/`fontWeight`) вместо CSS-модуля и токена.
- **FE-STY-X8.** Глобальные несколь-скоупленные стили (правка тегов/чужих классов вне `*.module.css`), протекающие на другие компоненты.

## 5. Чеклист подключения (React + TS, @design-system/components)
1. Есть аналог в ДС — берём компонент ДС (`Button`/`Input`/`Typography`/`Grid`), не сырой html.
2. Импорт — deep-import конкретного компонента/иконки, не пакет целиком.
3. Цвета/отступы/шрифты — из токенов и пропов ДС, без магических hex/px.
4. Layout — CSS-модули с доменными именами; инлайн-`style` только для динамики.
5. Не переизобретаем и не перекрываем `!important`-ом внутренности компонентов ДС.
