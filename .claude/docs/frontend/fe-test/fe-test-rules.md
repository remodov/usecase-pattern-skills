# Тестирование компонентов (React + TS, Jest + Testing Library)

> **Что это.** Concern `fe-test` трека `frontend` (стек React+TS). Single-stack → плоская форма: коды + интент
> + код-примеры внутри (отдельного style-guide нет). Коды: `FE-TEST-<N>` — обязательно, `FE-TEST-X<N>` —
> антипаттерн. Карта трека — `frontend/_index.md`.
>
> **Реализация под проект:** `jest` + `ts-jest`, запуск `jest --coverage`; `@testing-library/react`
> + `@testing-library/react-hooks`; `userEvent` для взаимодействий. Юзер-центричные запросы
> (`getByRole`/`getByText`/`getByLabelText`, `findBy*` для async). Рендер с провайдерами (Redux store + Router)
> через общий хелпер `renderWithProviders`. Имена тестов по-русски (`describe('…')`, `test('должна …')`).
> Связанные: `fe-component` (что тестируем — наблюдаемое поведение вью), `fe-state` (мок не лезет в slice —
> рендерим с реальным store), `fe-data-fetching` (мок на сетевой границе — fetcher/thunk), `fe-forms`
> (взаимодействие с полями через `userEvent`/лейблы), `fe-a11y` (роли как точка доступа в тесте).

## 1. Что тестируем (поведение, не реализация)
**MUST:**
- **FE-TEST-1.** Тестируй **наблюдаемое поведение** — что пользователь видит и делает (DOM/текст, навигация, вызванные наружу колбэки, отрисованный результат запроса), а не внутренний стейт, приватные функции или вызовы внутренних хуков.
- **FE-TEST-2.** Один тест — один сценарий поведения; имя описывает **ожидание пользователя** («должна показать ошибку при пустом ответе»), а не имя метода/реализацию.
- **FE-TEST-3.** Покрывай **значимые пользователю ветки** (загрузка / успех / ошибка / пустой список / запрет доступа), а не строки ради цифры coverage.

**MUST NOT:**
- **FE-TEST-X1.** Проверка внутреннего состояния/инстанса компонента, приватных функций или факта вызова внутреннего хука вместо DOM и поведения (`fe-component`: вью — это его вывод, не внутренности).
- **FE-TEST-X2.** `toMatchSnapshot` на всё как замена осмысленных assert'ов — снапшот фиксирует верстку, а не поведение, и зелёный после бездумного `--updateSnapshot`.

## 2. Юзер-центричные запросы и userEvent
**MUST:**
- **FE-TEST-4.** Находи элементы так, как их находит пользователь — по роли/тексту/лейблу (`getByRole('button', { name: … })`, `getByText`, `getByLabelText`); `findBy*` — для появляющихся асинхронно.
- **FE-TEST-5.** Пользовательские взаимодействия — через `userEvent` (`click`/`type`/`selectOptions`/`tab`), а не `fireEvent`: `userEvent` воспроизводит реальную последовательность событий (focus → keydown → input).
- **FE-TEST-6.** `getByTestId` — **запасной вариант**, только когда у элемента нет доступной роли/текста/лейбла; сначала добейся доступной семантики (cross-ref `fe-a11y`).

**MUST NOT:**
- **FE-TEST-X3.** Запрос по `className`/тегу/`getByTestId` там, где элемент имеет роль/лейбл/текст — тест ломается на рефакторинге стилей и не проверяет доступность.
- **FE-TEST-X4.** Привязка к порядку DOM/верстке (`nth-child`, индексы массива узлов, `container.querySelector`) вместо ролей/имён — хрупко к перестановке разметки.

## 3. Рендер с провайдерами и моки границы
**MUST:**
- **FE-TEST-7.** Компоненты, которым нужны провайдеры, рендерь через общий `renderWithProviders` (реальные Redux store + Router), а не голый `render` — тест проходит тот же путь, что и приложение.
- **FE-TEST-8.** Мокай **сетевую границу** (fetcher'ы / thunks / HTTP-клиент), а не внутренние модули компонента; компонент и реальный store в тесте остаются настоящими.
- **FE-TEST-9.** Изоляция теста: свежий store/состояние на каждый тест и очистка моков (`afterEach(() => jest.clearAllMocks())` / `cleanup`), без утечки состояния между тестами.

**MUST NOT:**
- **FE-TEST-X5.** Мок реализации — `jest.mock` на внутренние хуки/функции/селекторы самого компонента вместо границы: тест перестаёт проверять интеграцию вью+store и зеленеет при сломанной логике.
- **FE-TEST-X6.** Общий мутируемый store/состояние между тестами — порядок-зависимость и флаки; каждый тест поднимает своё окружение.

## 4. Async и конвенции именования
**MUST:**
- **FE-TEST-10.** Асинхронный UI ожидай через `findBy*` / `waitFor` / `waitForElementToBeRemoved`, а не произвольный `setTimeout`/фиксированную задержку; `await userEvent.…` для действий, вызывающих обновление.
- **FE-TEST-11.** Имена по-русски и осмысленные: `describe('<Компонент/фича>')`, `test('должна <ожидаемое поведение>')` — читаются как спецификация поведения.

**MUST NOT:**
- **FE-TEST-X7.** Жёсткий `setTimeout`/`sleep`/фиксированный таймаут вместо `findBy`/`waitFor` — флаки и медленные тесты, зависящие от скорости машины.
- **FE-TEST-X8.** Ручные `act(...)`-обёртки и подавление `act`-warning'ов вместо правильного `await findBy*`/`await userEvent` — warning сигналит о непрожданном async-обновлении, а не о шуме.

## 5. Чеклист подключения (React + TS, Jest + Testing Library)
1. Тестируем наблюдаемое поведение (DOM/колбэки), не внутренний стейт/приватные функции; имена `test('должна …')` по-русски.
2. Запросы по роли/тексту/лейблу (`getByRole`); `getByTestId` — только без доступной семантики; взаимодействия через `userEvent`.
3. Рендер через `renderWithProviders` (реальные store + Router); мок на сетевой границе (fetcher/thunk), не на внутренних модулях.
4. Async через `findBy*`/`waitFor`, без `setTimeout`; каждый тест изолирован (свежий store, `clearAllMocks`).
5. Покрыты значимые ветки (загрузка/успех/ошибка/пусто); без тотальных snapshot'ов и привязки к верстке.
