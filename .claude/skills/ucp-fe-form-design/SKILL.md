# Форма по контракту — проектирование

**Важно:** живого образца формы в шаблоне `next-ssr` нет — `POST /orders`
в контракте описан, а экрана создания не построено. Код формы берётся из
справочника скилла шаблона (`ui-from-openapi/references/skeletons.md`, раздел
про форму), а не копированием с соседнего экрана.

## Откуда берутся правила

`openspec/specs/**` проекта; сводка — `AGENTS.md`. Если шаблон принёс
`ui-from-openapi`, веди по его гейтам.

## Порядок

1. **Схема — из контракта, не из головы.** Поля, обязательность и границы
   берутся из сгенерированных zod-схем; значение, которого нет в контракте,
   не выдумывается (`content/no-invented-values`,
   `api/generated-code-immutable`).

2. **Варианты перечислений — из сгенерированного enum**, подписи — ключом-шаблоном
   словаря (`content/enum-labels-from-generated-enum`). Ключ надписи заводит тот
   экран, где кнопка нарисована (`content/label-key-owned-by-drawing-screen`).

3. **Состояние формы — в `model/`-хуке**, `ui/` только рендерит
   (`architecture/mvvm-model-view-split`). Отправка идёт сгенерированным хуком
   мутации (`api/network-via-generated-hooks`).

4. **Инвалидация — ключами из сгенерированного кода**
   (`api/invalidation-keys-from-generated`): ключ, написанный руками,
   компилируется и молча перестаёт обновлять список — гейта на это нет.

5. **Ошибки.** Ошибка поля привязана к полю и доступна с клавиатуры и скринридеру;
   ошибка формы показывается отдельно. 403 обрабатывается всегда, даже если
   кнопка была выключена (`auth/always-handle-403`).

6. **Доступность.** Поле связано с подписью, ошибка объявлена, фокус после
   отправки не теряется, сигнал состояния не только цветом. Гейта на это в
   шаблоне нет — держится тобой.

7. **Тест.** По MVVM: логика — юнитом на хук, вёрстка — на View
   (`testing/mvvm-test-split`), сеть — через MSW-стенд
   (`testing/msw-mock-required-in-tests`). Подробнее — `ucp-fe-test-design`.

8. **Гейты** — как у экрана: `lint`, `lint:arch`, `typecheck`, `map:check`,
   `test` (`tooling/gate-discipline`).
