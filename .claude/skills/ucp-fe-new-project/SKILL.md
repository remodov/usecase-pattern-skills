# Новый фронтенд-проект из шаблона

Проект не собирается с нуля: он приезжает из `<репозиторий шаблонов фронтенда>`, вместе
с требованиями, гейтами и своим процедурным скиллом. Твоя работа — выбрать
шаблон, довести проект до зелёных гейтов и передать дальше по цепочке.

## 1. Выбери шаблон по природе приложения

| Шаблон | Для чего | Что внутри |
| --- | --- | --- |
| `next-ssr` | публичное приложение с серверным рендерингом и SEO | FSD со слоем `_pages`, `openspec/specs`, скилл `ui-from-openapi` |
| `vite-spa` | админка или дашборд целиком за авторизацией | та же раскладка, без серверного рендеринга |
| `next-static` | лендинг, документация, блог | `app/` + `components/`, скилл `ui-from-figma` |

Спроси, если природа приложения не названа: выбор шаблона потом стоит переезда,
а не правки. **`openspec/specs` есть только в `next-ssr`** — в остальных
требования живут в `AGENTS.md` и `docs/`.

## 2. Заведи проект

```bash
./scripts/new-project.sh <шаблон> <директория>
```

Скрипт клонирует шаблон разреженной выборкой по SSH — репозиторий приватный,
обычные загрузчики шаблонов к нему не ходят. Директория не должна существовать.

## 3. Убери демо

`bun run demo:remove` удаляет демо-фичу целиком. Делать это **до** первого
своего экрана: демо тянет за собой словарь, карты экранов и тесты, и позже
удаление задевает уже свой код. Вместе с демо уезжают разделы `docs/rationale.md`,
объяснявшие удалённые файлы.

## 4. Настрой окружение

- Зеркала зависимостей — в `.npmrc`; его читают и `bun`, и остальные инструменты.
- Бинарники, которые зеркалом не покрываются: браузеры Playwright
  (`PLAYWRIGHT_DOWNLOAD_HOST`), `sharp` (`npm_config_sharp_binary_host`),
  остальное — через `HTTPS_PROXY`.
- Пакеты, которым нужен postinstall, перечисляются в `trustedDependencies`:
  `bun` не выполняет его по умолчанию.
- Стенды и переменные сверяются `bun run env:check` (`environment/*`).

## 5. Подключи контракт

Дальше — `ucp-fe-service-design`: контракт приезжает npm-пакетом из приватного
реестра точной версией, секция сервиса добавляется в `orval.config.ts`, клиент
и моки генерируются `bun run generate:api` (`api/contract-as-npm-package`,
`api/orval-section-shape`).

## 6. Прогони гейты и не оставляй красным

```bash
bun run lint:ci && bun run lint:arch && bun run format:check && bun run typecheck \
  && bun run env:check && bun run map:check && bun run test && bun run build
```

Требование `tooling/gate-discipline` запрещает сдавать работу с красным гейтом.
В `next-ssr` дополнительно есть `bun run spec:check` — он сверяет требования
и сводную таблицу в `AGENTS.md`, собираемую `bun run spec:sync`.

## 7. Передай дальше

Экран — `ucp-fe-screen-design` (в `next-ssr` он ведёт по собственному скиллу
шаблона `ui-from-openapi`, гейты 0–5). Форма — `ucp-fe-form-design`.
Права — `ucp-fe-auth-design`. Тесты — `ucp-fe-test-design`.

## Чего не делать

- Не переносить в проект правила из этой методологии: у фронта источник правды —
  требования шаблона.
- Не править сгенерированный клиент руками (`api/generated-code-immutable`).
- Не откладывать `demo:remove` на «потом»: позже он задевает свой код.
