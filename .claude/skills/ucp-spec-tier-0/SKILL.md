# Use Case спецификация — as-is реверс из кода

Ты пишешь **as-is спецификацию** существующего сервиса — снимок «как сейчас» в **том же формате**, что и `ucp-spec-design` (см. `.claude/docs/shared/spec-format/spec.md`, **прочитай первым делом**). Содержимое каждой секции — факт из кода; чего в репо нет — литерал `not-declared`.

As-is нужен для онбординга (структурированное описание вместо россыпи README) и как база для миграции (`not-declared`-поля подсвечивают, где сервис не следует UCP).

As-is читают люди, которые сервис ещё не знают, — поэтому спека пишется **как объяснение коллеге**, а не как дамп фактов: лид в начале, вводная фраза перед каждым разделом, источники вне текста, пробелы собраны в конце. Правила подачи — требования `spec-format/*`; они **не отменяют** обязательные реестры и таблицы, а окружают их прозой. Документ от этого длиннее — так и задумано.

Скилл **не классифицирует** код как правильный/неправильный, **не предлагает рефакторинг**, **не выдумывает агрегаты, акторов, цели команд или типы Context Mapping** там, где их нет в коде. Фиксирует факт, иначе `not-declared`.

## Зависимости

- Плагин `superpowers` — TodoWrite на крупных сервисах (не обязателен).
- Шаблон `.claude/docs/shared/spec-format/spec.md` — обязательный источник формата. Нет — остановись.
- `context7` и живая БД **не используются** — источник только репо.

## Инструкции

1. **Прочитай формат** из `.claude/docs/shared/spec-format/spec.md`.

2. **Имя сервиса** — из `build.gradle`/`pom.xml` (`rootProject.name`/`artifactId`), README или директории. Неоднозначно — спроси.

3. **Маркер Уровня 0.** В заголовке — `(Уровень 0, as-is)`, во frontmatter — `level: 0`. Уровень 0 — это спека из кода без бизнес-брифа. Наблюдаемую архитектуру (есть `usecase-pattern`/агрегаты/порты — кандидат на Уровень 2/3 при миграции, иначе Уровень 1) отметь прозой в §Bounded Context для планирования миграции, но сам as-is остаётся `level: 0`.

4. **Раскладка — всегда корень + `aggregates/`.** Корень `docs/spec/<service>-spec.md` (контекст) + `docs/spec/aggregates/<unit>.md` на каждый домен-юнит. На Уровне 3 юниты = агрегаты из кода (`AggregateRoot`); для anemic-кода (Уровень 1–2, агрегатов нет) — центральная сущность(и) из таблиц, всё равно отдельным файлом. frontmatter: `context` + `bounded-context` + `level: 0` (корень); `context` + `aggregate` + `level: 0` (юнит).

5. **Собери источники из репо → секции** (нумерация и имена — из шаблона):

   | Источник | Секция |
   |---|---|
   | README (назначение, границы) | Bounded Context; НФТ |
   | `build.gradle*`/`pom.xml`, `application.yml` | Техническая реализация (стек); Интеграции |
   | Миграции (Flyway/Liquibase), `@Entity`/`@Table` | Техническая реализация → «Схема БД» (ER, FK, индексы); список таблиц — в Доменную модель |
   | `enum`-статусы + поля `status` | Жизненный цикл |
   | `SecurityConfig`, `@PreAuthorize`, JWT | Роли и доступ |
   | `@Valid`/JSR-303, БД-`CHECK`/`UNIQUE`, `if(...) throw` | Бизнес-правила |
   | POST/PUT/PATCH/DELETE-endpoint, `@KafkaListener` | Команды |
   | GET-endpoint | Запросы |
   | `KafkaTemplate.send`/`@SendTo` | Доменные события (+ publish-рёбра в Интеграции) |
   | `@ExceptionHandler`/наследники `RuntimeException` | коды ошибок — в поле «Ошибки» команд (каталога ошибок нет) |
   | OpenAPI/Swagger | UI / контракты на рёбрах Интеграции |
   | DataSource/Kafka/`@FeignClient`/S3 из `application.yml` | Интеграции (рёбра) |
   | `@KafkaListener`, `KafkaTemplate.send`, `@JmsListener`/`JmsTemplate`, `spring.kafka.*` / очереди в `application.yml` | Техническая реализация → «Каналы и топики» (одна строка на канал) |
   | Все `@RequestMapping`/`@GetMapping`/`@PostMapping`/… + OpenAPI | Техническая реализация → «REST-поверхность» (одна строка на операцию) |
   | Интеграционные тесты `*IT.java`, `@SpringBootTest` | Use Cases; Критерии приёмки (GWT из `@DisplayName`) |
   | `@Transactional` поверх неск. ресурсов, `*_outbox`/`event_log`, `@Scheduled` over aggregates | Процессы (Saga) |

6. **Соблюдай тот же формат, что `ucp-spec-design`:** домен/техника разделены (схема БД, стек, Outbox, топики → только §Техническая реализация), команды/запросы — карточки, события — таблицей у агрегата + контракт в корне (при split), интеграции — нормализованный словарь, ссылки — якорные. Карточек-файлов на сущность/команду **не создаём** (это старый формат).

   **Два обязательных реестра в §11** (полный формат — в шаблоне, раздел «Обязательные реестры раздела „Техническая реализация“»; общее правило — `spec-format/lists-are-tables`):

   - подраздел **«Каналы и топики»** — единой таблицей фиксированного формата:

     `| Канал/топик | Направление (consume/produce) | Брокер/кластер | Consumer group / producer-id | Тип сообщения (payload) | Evidence (файл:строка) |`

     Одна строка на канал; канал, используемый в обе стороны, — две строки (`consume` и `produce`). Artemis/JMS и прочие не-Kafka очереди — **в той же таблице**, протокол пометкой в «Брокер/кластер» (`Artemis (JMS)`). Брокеров в коде не найдено — подраздел присутствует с явной пометкой **«не применимо: брокеров нет»**.

   - подраздел **«REST-поверхность»** — единой таблицей:

     `| Метод | Путь | operationId | Назначение | Evidence |`

     Одна строка на операцию (все `@*Mapping` + операции из OpenAPI). Путь не восстанавливается из кода (собирается в рантайме, задан внешним конфигом) — строка с `not-declared` в колонке «Путь», **а не пропуск**. REST-endpoint'ов нет — пометка «не применимо: REST-endpoint'ов нет».

   Заголовки колонок обоих реестров — **дословно** как в шаблоне, не переименовывай и не переставляй. Неизвестная ячейка — `not-declared`, но **строка присутствует всегда**: отсутствующая строка = потерянный факт, строка с `not-declared` = видимый пробел. Evidence — `путь/Файл.java:142` (для канала — место `@KafkaListener`/`send`, для операции — место маппинга); не нашёл — `not-declared`.

7. **Напиши лид** (`spec-format/document-opens-with-lead`) — раздел `## О сервисе` сразу после заголовка, до §1, 5–10 строк прозой, три абзаца: **чем занимается сервис** (своими словами, не цитатой README), **2–3 главных потока** (кто инициирует → что происходит → чем заканчивается), **2–3 особенности или риска** (асинхронная согласованность, ручные шаги, привязка к операционному дню, узкое место по времени ответа, легаси-костыль). Образец — в шаблоне.

   В лиде **нет** кодов правил, evidence-ссылок, литерала `not-declared` и таблиц: он резюмирует то, что ниже раскрыто подробно и с источниками. Не знаешь, какие потоки главные, — возьми те, через которые идёт больше всего кода: самый нагруженный listener, самый крупный контроллер, шедулер с самым широким охватом. В файле домен-юнита — `## О юните` на 2–3 строки (`spec-format/document-opens-with-lead`): что моделирует, как живёт, что неочевидно.

8. **Подача внутри разделов.**

   - **Вводная фраза перед таблицей** (`spec-format/section-opens-with-prose`): каждый раздел и подраздел открывается 1–3 предложениями — что здесь, зачем читателю, на что смотреть в первую очередь. Голая таблица под заголовком — нарушение. Фраза **не пересказывает** строки таблицы (это вернуло бы прозу вместо реестра, `spec-format/lists-are-tables`).
   - **Таблица — не шире 6 колонок** (`spec-format/table-fits-six-columns`). Нужно больше — две связанные таблицы по общему ключу: «что это» и «как настроено», ключ дословно одинаковый в первой колонке обеих. Обязательные реестры §11 в лимит укладываются и **не меняются**; новый атрибут канала — второй таблицей с ключом «Канал/топик», не седьмой колонкой.
   - **Язык** (`spec-format/language-is-plain`): короткие предложения, активный залог, конкретное подлежащее («шедулер переотправляет невыгруженные записи», не «осуществляется переотправка»). Термины — из глоссария §3, без синонимов и транслита.

9. **Все секции присутствуют всегда.** Если в коде нет, например, `KafkaTemplate.send` — раздел «Доменные события» содержит пометку «Сервис не публикует событий (`KafkaTemplate.send`/`@SendTo` не найдены)», а не молчаливое опущение.

10. **Литерал `not-declared`** — для отсутствующих данных (актор команды, идемпотентность, тип Context Mapping, SLA, инварианты агрегата, владелец). Не пустая строка, не `null`, не TODO. Но **место литерала ограничено** (`spec-format/unknown-cell-is-marked`): ячейки таблиц и размеченные поля карточек, где без него утверждение читается неверно (`Идемпотентность: not-declared`). В прозе разделов литерал не рассыпаем.

    **Собери пробелы в хвост** (`spec-format/gaps-collected-at-the-end`): последний раздел документа — ненумерованный `## Что не определено`, вводная фраза + таблица `| Раздел | Чего нет | Чем закрыть |`. Родственные пробелы — одной строкой («акторы всех команд контроллера», «типы Context Mapping всех рёбер»), а не построчно: раздел показывает масштаб незнания, а не его длину. Корень собирает пробелы контекста, файл юнита — свои. Пробелов нет — раздел с пометкой «пробелов нет». Для anemic-модели §Доменная модель помечает «агрегаты в коде не выделены (anemic); модель = таблицы, см. Техническая реализация → Схема БД».

11. **Источники — вне предложений** (`spec-format/evidence-outside-the-sentence`). As-is целиком построен на evidence, поэтому ссылки на код собираются, а не вставляются в текст:

    - в таблицах — **колонка `Evidence`** (`путь/Файл.kt:142`); имя колонки не переименовывается;
    - под разделом — блок **«Источники раздела»** последней строкой: `**Источники раздела:** KafkaConfig.kt:41–58 (кластеры), AccountService.kt:112 (раскладка inbox), db/changelog/2024-03-blocking.xml`;
    - альтернатива — markdown-сноски `[^1]` со списком в конце раздела.

    В прозе допустимо **имя класса или файла без номера строки**, если без него фраза непонятна («раскладку inbox делает `AccountService`»). Конструкция `(SomeService.kt:142)` внутри предложения — нарушение (`spec-format/evidence-outside-the-sentence`); прежняя пометка `(reconstructed-from: …)` в прозе тоже: реконструкция помечается в колонке `Evidence` или в блоке «Источники раздела» тем же токеном `reconstructed-from:`.

12. **Код не пиши.** Только markdown-спека. Никаких рефакторингов и `// TODO migrate` в исходниках.

13. **Самопроверка:**
    - Заголовок несёт `(Уровень 0, as-is)`; раскладка — корень + `aggregates/<unit>.md`; frontmatter несёт `level: 0`.
    - Все секции созданы; пустые — с явной пометкой об отсутствии.
    - Техника (схема БД, стек, топики) — только в §Техническая реализация; §1–§10 без неё.
    - Отсутствующие данные = `not-declared` (в ячейках и полях карточек); реконструкции помечены токеном `reconstructed-from:` — в колонке `Evidence` или в блоке «Источники раздела», не в прозе.
    - §11 содержит подраздел «Каналы и топики» единой таблицей фиксированного формата (или пометку «не применимо: брокеров нет»); одна строка на канал, Artemis/JMS — в той же таблице.
    - §11 содержит подраздел «REST-поверхность» таблицей `| Метод | Путь | operationId | Назначение | Evidence |`; операции с невосстановимым путём — строкой с `not-declared`, не пропуском.
    - Заголовки колонок обоих реестров дословно совпадают с шаблоном (`spec-format/lists-are-tables`); ни одна строка не выброшена из-за неизвестных значений.
    - Не выдуманы бизнес-факты (акторы, цели, типы связи), которых нет в коде.
    - За лидом идёт врезка `## Важно знать` (`spec-format/key-facts-box-after-lead`): 5–7 буллетов простым языком — главный инвариант, что согласовано отложенно, что делается вручную, жёсткое ограничение, частая ошибка новичка. Перечисление разделов врезкой не считается.
    - Подзаголовки и карточки названы утверждениями на языке домена (`spec-format/subheadings-are-statements`): «Заказ нельзя отменить после отгрузки», код правила — рядом, не вместо.
    - Вводная фраза каждого раздела называет, на что смотреть первым (`spec-format/intro-names-what-matters`); «здесь перечислены X» — не вводная.
    - Каждое бизнес-правило несёт колонку последствия (`spec-format/business-rule-states-consequence`): что ломается и для кого в терминах бизнеса, а не «нарушается инвариант».
    - В файле юнита есть раздел `## Частые ошибки` (`spec-format/unit-lists-common-mistakes`): таблица «ошибка · что ломается · как правильно» про этот домен, а не общие советы.
    - Файл юнита заканчивается блоком `## Куда дальше` (`spec-format/file-ends-with-navigation`): куда идти за смежным знанием и что там найдётся.
    - Каждый файл открывается лидом (`## О сервисе` / `## О юните`) до §1, прозой, без кодов, evidence и `not-declared` (`spec-format/document-opens-with-lead/2`).
    - Ни одна ссылка `Файл.kt:NNN` и ни одна пометка `reconstructed-from:` не стоит внутри предложения — только колонка `Evidence`, блок «Источники раздела» или сноска (`spec-format/evidence-outside-the-sentence`).
    - Литерал `not-declared` в прозе не рассыпан; пробелы собраны в хвостовой `## Что не определено` с таблицей `| Раздел | Чего нет | Чем закрыть |`; в ячейках таблиц и полях карточек литерал сохранён (`spec-format/gaps-collected-at-the-end/2`).
    - Ни одна таблица не шире 6 колонок; широкие разбиты на две связанные по общему ключу; реестры §11 не расширены (`spec-format/table-fits-six-columns`).
    - Ни один раздел не начинается сразу с таблицы — везде 1–3 вводных предложения (`spec-format/section-opens-with-prose`).
    - Текст читается вслух: короткие предложения, активный залог, термины из глоссария (`spec-format/language-is-plain`).

14. **Структура вывода:**
    1. Резюме: имя сервиса, статистика (N таблиц, M команд, K событий, L ошибок, P интеграций, C каналов, E REST-операций), `(Уровень 0, as-is)`, наблюдаемая архитектура (для миграции), источники.
    2. Дерево созданных файлов в `docs/spec/`.
    3. **Список явных gap-ов** — ссылкой на раздел `## Что не определено` каждого файла (там он уже собран таблицей) + счётчик строк по файлам; в ответе не дублируй таблицу целиком, назови 3–5 самых дорогих пробелов.
    4. Следующие шаги: as-is спека читается downstream-review-скиллами; при миграции команда заменяет `not-declared` на реальные значения.
