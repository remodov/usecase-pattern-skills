# Потоковые соединения — проектирование (Java / Spring Boot)

## Инструкции

1. **Прочитай** `.claude/docs/backend/streaming/spec.md` и `references/java/implementation.md`. Связанные: `backend/auth-patterns/spec.md` (проверка прав), `backend/pg-runtime/spec.md` (короткие транзакции), `backend/observability/spec.md` (метрики), `backend/graceful-shutdown/spec.md` (закрытие соединений при остановке).

2. **Выбери механизм по природе обмена** (`streaming/mechanism-matches-exchange`): односторонняя лента — `SseEmitter`; двусторонний обмен — Spring WebSocket; большая выгрузка — `StreamingResponseBody`. Решение запиши в спеку сервиса.

3. **Заложи обязательное:**
   - аутентификация при установлении соединения, проверка прав на подписку, переучёт по сроку токена;
   - ограниченная очередь на получателя и предел соединений на экземпляр;
   - поддержание активности и тайм-аут простоя;
   - отмена серверной работы и снятие подписки при разрыве;
   - чтение порциями короткими транзакциями, без удержания соединения с базой;
   - рассылка через общий канал (Redis pub/sub или брокер), а не локальный реестр соединений;
   - метрики соединений без содержимого сообщений.

4. **Самопроверка** и предложи `ucp-streaming-review`.

## Чего не генерировать

- Проверку прав только на входе без проверки на подписку.
- Неограниченную очередь событий на получателя.
- Транзакцию или соединение с базой, удерживаемые на всё время потока.
- Локальный реестр соединений как механизм рассылки при нескольких экземплярах.
