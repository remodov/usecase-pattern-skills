## Use Case Pattern skills

Проект использует методологию Use Case Pattern: скиллы `ucp-*`, корпус требований
в `.claude/docs/` и always-loaded ядро языка в `.claude/rules/` подключены через
`install.sh` из репо claude-code-java (справка — его README). Всё между маркерами
`BEGIN ucp-skills` / `END ucp-skills` перезаписывается установщиком — своё пишите
снаружи маркеров.

### Язык общения

Ответы, планы, коммиты, summary — **по-русски**; идентификаторы и термины —
латиницей, как в коде (`UseCase`, `Aggregate`, `Repository`, имена классов и
таблиц). Пользователь пишет по-английски — отвечаем по-английски.

### Размер ответа

Размер ответа равен размеру вопроса. Решения и затронутые файлы — всегда; полные
файлы — только когда просят сгенерировать; дерево файлов, audit-таблицы, «что не
покрыто» — по запросу. Ревью после design-скилла — по запросу, не автоматически.
Обязательное ревью — для рукописного кода и **всегда** для DDL и миграций
(`ucp-pg-schema-review`, `ucp-pg-migration-review`).

### Правила и как их читать

Требования — `.claude/docs/<трек>/<домен>/spec.md`, по файлу на домен. Единица —
требование с ID вида `<домен>/<имя>` и полями **Гейт** (чем ловится), **Покрытие**
(полное / частичное / нет, по худшему языку) и **Не ловит**.
59 % корпуса держится ревью — там единственная защита — внимательность
читающего. Примеры — `<домен>/references/<язык>/`. Читай нужное требование по
ID, не весь файл.
Гейты проекта заводит `ucp-bootstrap-design`, каталог —
`.claude/docs/_meta/project-gates.md`; обещанный, но не заведённый гейт —
отдельная находка ревью, важнее единичного нарушения.

Ядро языка (`.claude/rules/ucp-<lang>-core.md`) уже в контексте — на него
ссылаются, его не пересказывают. Если в проекте есть `docs/spec/` — это источник
правды по сервису (корень `docs/spec/<service>-spec.md`, агрегаты —
`docs/spec/aggregates/<name>.md`); читай корень в начале сессии.

### Работа — через скиллы

UCP-артефакты (спека, агрегаты, операции, контракт, адаптеры, миграции, тесты)
делаются соответствующим `/ucp-*` скиллом, не от руки — иначе код дрейфует, а
review-скиллы ругаются. Пары по concern'у: `ucp-<concern>-design` ↔
`ucp-<concern>-review`; что установлено и почему — в таблице «Установленный срез»
ниже. Скилл вызывается через `Skill` в текущей сессии (или `/ucp-...`), не через
`Agent`-форк: форк стартует с холодным кэшем и не видит соседей; несколько ревью
— последовательно.

Фразы «сделай / пишем / новый / напиши / начнём / сгенерим сервис» — триггер
цепочки: запусти `/ucp-new-service` (спека → DDD → bootstrap → операции →
авторизация → тесты). Хуки в `.claude/settings.json` делают триггер и проверки
детерминированными (`ucp-trigger-detect.sh`, `ucp-session-check.sh`,
`ucp-post-skill-review.sh`). Если `ucp-*` скиллов нет в available-skills —
сессия запущена не из директории сервиса: скажи «перезапусти Claude из
`/path/to/service`», структуру не изобретай.

### Планы

План режется на вертикальные срезы: фаза = одна команда или запрос целиком
(контракт → операция → репозиторий → миграция → тест), собирается и проверяется
до следующей; инфраструктурный bootstrap — фаза 0, единственная горизонтальная.
Шаги плана называют конкретные `/ucp-*` скиллы, шаг ревью — отдельно.
